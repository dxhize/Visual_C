Architecture · one recording, many qualified readers #

Level 1 · Intuition #

The system has two non-interchangeable jobs. The Trace Engine gathers bounded observations while a compiled C program runs under GDB; the Trace Parser lets other code navigate that finished recording safely. A JSON trace is the contract between them. No parser query can revisit an inferior or recover an event that the engine did not capture.

Level 2 · Pipeline and boundaries #

  1. A TraceConfig describes sources, program arguments, tools, limits and optional tracing modes. GCC builds a debug executable with an allocator wrapper and prepares a separately sanitized executable. Compilation failure has diagnostics but no fabricated stops.
  2. The engine extracts static DWARF from the GCC artifact and optionally runs a Clang AST pass. GDB/MI observes one followed inferior, source checkpoints and instruction attempts. The wrapper appends PID-local heap events. Analyses have separately recorded outcomes.
  3. One DebugSessionTrace preserves original observations, metadata, reports and scope/gaps. The recorder can append JSONL records during execution, but a JSONL journal is not a complete JSON trace.
  4. TraceStore::open parses the JSON, checks schema version and builds immutable position indexes. validated_semantic() performs one opt-in deep validation pass; TP-7 composes qualified borrowed views in explicit pages of at most 128.
  5. A future Stage 2 consumer may compute explanations from these citations. Its interpretations must not be confused with primary observations.

Distinct evidence providers #

ProviderWhat it knowsWhat it does not establish
GCC + DWARFCompiled types, declarations, debug layout, diagnosticsDynamic value or initializer execution
GDB/MIStopped frame, source line, values and bounded memory readsAll execution between stops or other processes
C allocation wrapperPID/sequence-tagged intercepted allocator callsInternal allocations in unwrapped libraries
Clang AST (optional)Candidate syntax and source spansThat an expression executed
Valgrind / ASan / UBSanDiagnostics from independent reproductionsIdentity of a primary-run allocation

Level 3 · Trace through the implementation #

src/trace.rs::trace_program calls ExecutionLimits::validate, enters a supervisor::scope, probes tools, invokes compiler::compile_project, extracts DWARF with dwarf::extract_excluding, and conditionally runs clang_ast::analyze. Its stopped loop cooperates with src/gdb_mi.rs, src/recorder.rs and src/allocation_tracker.rs. After reconstructing lifetimes and optional evidence fusion, src/models.rs defines the serializable result. src/json_export.rs writes an individually capped JSON document. src/trace_parser/mod.rs::TraceStore::assemble stores Arc<DebugSessionTrace> plus Arc<TraceIndexes> without copying source records.

Is this datum an observation, a static candidate, a recorded association, a validation finding or a future interpretation? See confidence for the rules that keep those categories separate.
