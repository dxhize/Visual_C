37 · Trace Engine source file handbook #

In one sentence: This is a reading guide for engine source files, not a claim that you need to understand every helper before using the trace.

Key terms #

TermPlain meaning
OrchestratorCode such as trace.rs that decides which stage runs next and handles its result.
File chapterA focused explanation of the responsibilities and limitations of one source file.

Example. Start with trace.rs to see the big sequence, then visit gdb_mi.rs if your question is about debugger replies, or allocation_tracker.rs if it is about heap events.

>

What not to assume: Source file order is not the same as runtime execution order, especially for optional or failed stages.

The big picture #

This is the coverage index for the DOC-2 engine handbook. Each row names a production Stage 1 file, its ownership boundary, and the detailed chapter that explains its types, functions, state and failure behavior. The function reference is generated from reviewed graph nodes; the complete lexical symbol index remains in functions.

How to use the handbook #

Start with entry and orchestration, then follow the execution path through compilation, GDB/MI, stopped-state capture, heap reconstruction, static metadata, diagnostics and export. A file's presence here means it has a detailed chapter; it does not mean every private helper has an independently reviewed walkthrough. Source locations are from the inspected worktree, not a claim that historical line numbers remain stable.

Excluded from this handbook #

src/trace_parser/ is Stage 1 Trace Parser material reserved for DOC-3. src/semantic/ is Stage 2 implementation and is outside this documentation project. The shared schema and identity reference describes the wire contract consumed by both engine and parser, but it is not an engine-internals chapter.

Coverage status #

The machine-readable inventory marks these files as having a detailed chapter. Graph-linked functions carry reviewed purpose, inputs/outputs, limitations and classified relationships. Other indexed functions are deliberately marked as source-located but not yet deeply walked through; DOC-2 does not turn a lexical definition match into a call or a behavioral proof.
