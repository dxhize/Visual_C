# Stage 2 / SE-2 — observed memory layout and qualified typed-byte interpretation

**Decision:** SE-2 provides a read-only, bounded layout/byte-pattern API on the completed SE-1 registry. Stage 1 remains frozen: schema v2, V2.1 import, TP-6/7, validation, process coverage, and canonical `Arc<DebugSessionTrace>` ownership are unchanged. There is no pointer graph, ownership inference, execution simulation, state difference, diagnostic engine, or SE-3/frontend work.

## 1. Architecture, ownership and handoff

`src/semantic/layout.rs` extends `src/semantic/` without changing the SE-1 identity/lifetime index. `LayoutEngine::new(&registry)` borrows the validated SE-1 `ObjectRegistry`; `LayoutEngine::with_target` additionally accepts a caller-provided target descriptor inspected from an ELF. `layout_for_object(&ObjectId, checkpoint)` returns one `MemoryLayout` for **exactly one** retained observation, or `Absent`/`Ambiguous`. `layout_for_observation(&ObservationView)` selects an exact record. Both check the SE-1 trace-scoped identity first; an independent load of equal JSON is foreign. A layout owns an SE-1 `ObjectId` handle and retains the observation's checkpoint and `EvidenceLocation`. It borrows the original `VariableInfo` or the **checkpoint's original** `HeapBlockInfo` memory evidence and hex string; it does not copy memory buffers, clone a DWARF registry, reuse final heap bytes for a previous stop, or turn a subobject into an independent SE-1 object.

```rust
// API excerpt; runnable trace/ELF example: examples/semantic_se2_bench.rs.
let view = store.validated_semantic();
let registry = ObjectRegistry::build(&view)?;
let engine = LayoutEngine::new(&registry); // no assumed host endianness
let layout = engine.layout_for_object(&object.id, checkpoint)?;
let root = layout.root();
let n = layout.children_count(&root)?;
for child in layout.children_page(&root, 0..n.min(64))? {
    let captured_prefix = layout.capture(&child); // borrowed hex; may be partial
    let decoded = layout.decode(&child); // unavailable until target format supplied
    println!("{:?} {:?} {:?}", child.path, captured_prefix.byte_range, decoded.status);
}
// Request subsequent explicit pages; do not imply the first page was complete.
```

**Exact SE-3 handoff:** retain `MemoryLayout::owner()`, `checkpoint`, `evidence_location`, the SE-1 `RuntimeObject`, and each `LayoutNode::path`; render recorded `offset`, `size`, `alignment`, `bit_range`, `kind`, `overlaps_storage`, `alternative_union_view`, `original_type_id` and `canonical_type_id`. For member names use `member_name`; for dimensions inspect the borrowed `type_entry().dimensions`. Page children explicitly with `children_count`/`children_page`, or request one `member`/`array_element`. Display `Capture::byte_range`, `requested_range`, borrowed `hex`, `historical` and confidence separately from `DecodeResult::{status,confidence,value}`. Do not concatenate addresses into IDs or treat decoded numeric pointers as links. There are no stable cross-checkpoint subobject identities: paths are scoped to this observation only.

## 2. Recorded DWARF resolution and type identity

`TypeRegistry` entries have trace-local `id` and `unit_id`, `kind`, `name`, optional `byte_size` and `encoding`, optional `referenced_type`, aggregate `members`, array `dimensions`, and enum `enumerators`. The TP-2 type index resolves the **actual type ID**; TP-6 validates the view once before SE-1 construction. Typedef, `const`, `volatile`, `restrict` and supported `atomic` wrappers retain `original_type_id` while following `referenced_type` to the **canonical** type; names are display metadata only. Missing/invalid references and cycles become opaque with an explicit `unavailable_reason`; no guessed C type or extent. Pointer pointees are *not* expanded. Recursive `struct Node { int value; struct Node *next; }` therefore terminates at `next`'s pointer storage. Metadata recursion is limited to 16 links; layout depth is 16, at most 1,024 aggregate members are evaluated, and each explicit child page is at most 64 items.

DWARF units record **address size** but this V2.2 `TypeEntry` does **not** serialize `DW_AT_alignment`; `LayoutNode::alignment` is `None`, never a natural-alignment guess. `UnitInfo::address_size` is checked when decoding. `TypeEntry::byte_size` and GDB's per-stop `runtime_size_bytes`/`size_bytes` are different authorities. An actual GDB runtime size takes priority for a root variable. Heap extent is its observed block size; a heap allocation has no proven struct type just because a pointer/source expression resembles one. Untyped heaps remain useful opaque byte regions.

## 3. Structs, unions, arrays, bitfields

Struct members use the compiler's recorded `byte_offset` and type/member byte size, not declaration-order packing. With known member spans, the engine reports inter-member and tail **byte padding**. If member storage is missing, it reports `Unknown` instead, not alleged padding. Overlapping members are flagged on *both* views. Packed/unaligned members use their actual recorded offsets without alignment assumptions. A flexible array's statically known struct prefix is retained; its missing tail count remains `UnknownExtent`. Allocation size alone never yields a flexible-array length. If an imported member exceeds the containing extent, a recorded fixed composite/array size conflicts with its runtime extent, or arithmetic overflows, the query explicitly errors instead of returning a plausible layout.

Union members are alternative, overlapping *interpretations*, with `alternative_union_view=true`. SE-2 does not choose an active member from identical bytes. For DWARF `DW_AT_data_bit_offset` plus `DW_AT_bit_size`, bit ranges are absolute from the containing object's start, shared byte spans are marked as overlapping, and signed bit widths are sign-extended only under a separately supplied **little-endian** target descriptor. `unclaimed_bits(&struct_node)` exposes bit positions not covered by member metadata; it is **not** a proof of compiler padding, initialization, or unused storage-unit semantics. Where bitfields occur, gaps are `Unknown`, not definite padding. Historical `DW_AT_bit_offset` has different storage-unit-relative conventions; SE-2 preserves raw storage and reports `AmbiguousBitOffset`. Big-endian bitfield extraction remains unavailable until the actual bit-numbering convention is verified. No `offsetof` is applied to bitfields.

Arrays use recorded dimension order/count/lower bound, canonical element size, and checked multiplication for row-major strides. Single elements are addressed directly, with no eager million-node expansion; a `0..65` request fails `PageLimit` instead of silently truncating to 64. An unknown dimension remains unknown except for **one** unknown dimension on a root array with GDB's **recorded runtime sizeof**, exact divisibility by known element/dimension sizes, and a matched array type. For a VLA nested in a struct/flexible tail or multiple unknown dimensions, no runtime count is inferred. Extremely large dimensions and bad offset arithmetic fail explicitly. Fixed array shapes remain visible even when zero bytes were captured.

## 4. Captured memory versus readable C values

Variables use TP-6 `MemoryEvidenceView::valid_range`: full, partial/truncated, unreadable and missing bytes remain distinct. Heap checkpoint blocks use the same qualified status/captured-hex checks on the *checkpoint's* block; SE-1 final `HeapEvidence::memory` is deliberately **not** substituted. The only borrowed raw bytes for a child are its actual captured prefix; no copied, zero-filled or post-free buffer exists. `capture()` separately reports requested node range and captured range/confidence. A successful debugger read or even complete captured padding is not proof of C initialization; a failed read is not a free. Historical heap bytes are marked `historical=true`. A later free/address reuse cannot rewrite an earlier stopped-state layout. Source `value`, pointer `points_to`, AST calls, Valgrind addresses and source-type candidates do not create typed heap objects.

**Target representation:** schema-v2 traces contain CU address size, but **no recorded target endianness, integer representation or verified ELF identity**. `LayoutEngine::new` therefore still supplies layout and raw bytes, but typed decoding returns `NoTargetByteOrder`. `TargetFormat::inspect_elf(path)` examines a **caller-supplied** ELF's header using the repository's existing `object` dependency; it does not silently use host architecture or a possibly removed session path, nor does it establish that a separately rebuilt ELF is byte-for-byte the original inferior. The caller must independently verify that this ELF represents the trace target; `with_target` is an explicit opt-in. CU address size must match the descriptor. Only x86/x86-64 descriptors opt into the known flat numeric pointer and IEEE binary32/64 formats. A caller can construct the public descriptor for controlled imported traces, but that is **not** a proof of its relationship to another trace. Decoded byte-pattern confidence is at most `Candidate`, even on a fully captured scalar: **not a definite initialized C value**.

Supported patterns: signed/unsigned DWARF integers and signed/unsigned chars up to 128 bits (including three-byte widths), `_Bool` only for 0/1, enum numeric values and a unique symbol if one is recorded (duplicate symbols remain numeric), numeric pointer storage only under a known flat representation, and IEEE binary32/64 where the verified architecture supports it. Enum high-bit values lacking signedness evidence stay unavailable; unknown enumerators remain numeric. Unsupported floating widths and signaling-NaN patterns stay unavailable. Captured partial scalars report `PartialBytes`, not a zero-padded value. Decoding `Address(n)` does **not** establish target object, pointer provenance, validity, ownership, aliasing or lifetime. Unions' alternative decodes are byte-pattern views, not assertions that all alternatives have simultaneously valid C values.

## 5. Permanent tests and native compiler oracles

`tests/semantic_layout_se2.rs` has **8** synthetic adversarial/representation tests; `tests/semantic_layout_se2_live.rs` runs **1** real, compiled native fixture test. Together they cover signed/unsigned/nonstandard-width integers and both byte orders; chars/char arrays, bool and invalid bool, enums and duplicate symbols, IEEE/unsupported/signaling float formats, pointer-sized numbers, partial/unreadable/missing bytes, typedef/const/volatile canonical IDs, struct padding and packed offsets, nested structures, union alternatives, arrays of structs/pointers, multidimensional arrays, 1-billion-element bounded paging, root VLA inference, unknown flexible tail, recursive pointer storage, modern shared signed/unsigned bitfields, unsupported legacy/big-endian bitfield conventions, metadata cycles/overflow, foreign refs, same-address heap reuse, historical untyped heap bytes and V2.1 with missing metadata. Imported duplicate DWARF IDs and structurally corrupt traces are rejected by the unchanged SE-1/Stage 1 gate.

The **positive oracle** is `fixtures/c/semantic_se2_layout.c`, independently compiled with GCC (`-O0 -g -gdwarf-5`). The native executable prints `sizeof` and legal `offsetof` results, while a *fresh* Engine → parser → validated TP-6 → SE-1 → SE-2 run yields bytes and DWARF offsets. On the tested GCC/x86-64 environment, the native values were: `Plain` size **12**, count offset **4**, tail offset **8**; packed size **5**, count offset **1**; bitfield struct size **4**; recursive `Node` size **16**, pointer offset **8**; nested struct size **32**, inner node offset **16**; matrix and two `Plain` rows each **24** bytes. Tests compare the actual node offsets/sizes with these *native output values*, not with hardcoded textbook layouts; the bitfield oracle compares decoded bytes with independently assigned C field values `5`, `-3`, `257`, not forbidden bitfield `offsetof`. Additional captures assert `sample.count=0x01020304`, `sample.tail=-2`, packed count `0x10203040`, nested count `27` and node value `17`, matrix `[1][2]=6`, rows `[1].count=9`, unique enum `DARK=-2`, float `1.25`, double `-2.5` and per-run numeric self-pointer bytes without promoting equality to provenance. All typed values remain qualified patterns, not initialized-memory certification.

The integration fixture ran with `gcc` and `gdb` available; the test explicitly skips that portion if either is absent. Synthetic tests exercise big endian without guessing the host's bitfield convention. `fixtures/c/runtime_memory_aggregates.c` supplies an additional real 20,000-element array whose capture is capped at a **4,096-byte prefix** for performance evaluation. The historical 900-stop/3,143-instruction fixture and heap-heavy traces are reused unchanged from Stage 1.

## 6. Complexity, resource bounds and release benchmarks

SE-2 construction borrows SE-1 and stores only a target descriptor: **O(1)** time and zero requested heap bytes in the measured release build; it does *not* interpret all checkpoints up front. Root resolution is bounded by 16 metadata links, no heap allocation; an indexed array element is O(dimensions + bounded type chain), with a small owned path; composite membership enumerates at most 1,024 members, allocates temporary descriptors, and returns one path. Pages allocate at most 64 child descriptors. `unclaimed_bits` enumerates at most 1,024 member spans; no global cache or repeated full-trace validation. Representation decode touches at most 16 borrowed bytes. A 20,000-element array does not create 20,000 retained nodes. An individual query can error (`DepthLimit`, `UnknownExtent`, `Overflow`, `Inconsistent`, `PageLimit`) rather than guessing or silently discarding a child.

Reproduce one workload per process (release build; **three independent runs per file**, 512 warmed queries per reported per-query median):

```sh
cargo build --release --example semantic_se2_bench
target/release/examples/semantic_se2_bench /tmp/cte-se2/layout.json /tmp/cte-se2/target_semantic
# Without independently checked ELF, layouts still work; typed decode is unavailable.
```

## 7. Limits and verification

- Target byte order, pointer format and ELF identity are **not guaranteed by schema v2**. Without an independently associated ELF, shapes and borrowed hex work, but typed interpretation intentionally does not. Exotic float/pointer formats, signaling NaNs, big-endian bitfields and legacy bit-offset conventions remain unavailable. C initialization, indeterminate/trap state, union active-member selection and pointer validity are not established even for fully captured bytes.
- Static DWARF cannot supply missing array bounds, packed alignment values or flexible-tail length. Compiler/debugger metadata can be incomplete, incorrect or maliciously imported; Stage 1 validation rejects its known structural contradictions, and SE-2 checks boundaries/type cycles on access. Layouts are bounded, **not** an assembled-trace RSS guarantee. A returned candidate byte-pattern interpretation is not a definite C semantic value.
- Existing Stage 1 evidence guards still apply: no address-as-provenance, AST-as-execution, independent Valgrind-as-primary allocation, silent-descendant completeness, or JSON-export-cap-as-RAM-bound. No Stage 1 or SE-1 identities, schemas, validation rules or TP-6/7 APIs were modified.
