# TP8-F01 — Realloc predecessor identity and confidence repair

**Scope:** targeted Trace Parser V2.2 correction, not a Trace Engine change, Semantic Engine, frontend, TP-9 or Stage 1 integrated audit. Read with `trace-parser-v2.2-final-audit.md` and `trace-parser-v2.2-tp8-reproducer.json` (the original TP-8 conditional verdict was correct **before** this repair).

## Root cause, reproduction and correction

`validate_heap` previously checked whether a predecessor ID existed, not whether the canonical creation event for the **new** allocation was a `Reallocated` event from that exact predecessor. TP-6 `heap(id)` then promoted a `heap_state.realloc_from_id` to `Definite` when both lifetimes existed and the observed-PID history was marked complete. TP-8's one-field import changed block 1's predecessor to ID 2 even though raw event 1 is `Allocated` (no old ID) and event 2 is the realloc *successor* from 1. `from_trace` correctly allowed this schema-compatible import, but deep validation incorrectly called it structurally sound; semantic confidence was falsely definite.

Permanent `tests/trace_parser_realloc_f01.rs::original_fabricated_existing_predecessor_must_never_be_definite` failed **0/1 before** the repair: `/tmp/cte-f01-before.log` shows a sound report with only legacy pointer-provenance unavailable and optional sanitizer findings. This test uses the checked-in engine-produced `tests/fixtures/stage1/realloc_move.json`, with a scoped observed-history annotation and one forged block predecessor; its raw event relationships are asserted first. The *original* full TP-8 fresh-engine mutation (`/tmp/cte-tp8/small.json`, original raw event 1 `Allocated`, one JSON-pointer edit `/heap_state/0/realloc_from_id ← /heap_state/1/allocation_id`) is also replayed using `examples/trace_parser_tp8_mutate.rs`. After repair: **`REALLOC_LINK_CONTRADICTORY` and `REALLOC_LINK_CYCLE` structural findings**, `old_id=Some(2)` remains raw/borrowed but `realloc_confidence=Contradictory`; `/tmp/cte-f01-mutator-last.log`. The same probe checks the self-link; a different existing but incorrect ID no longer passes by mere presence. No import was silently rewritten, and `from_trace` remains schema-only.

`src/trace_parser/validation.rs` now shares a small, read-only `realloc_link` evidence check with `src/trace_parser/semantic.rs`. Per new allocation ID, it compares only indexed creation events **for the new and predecessor IDs**, requiring a `Reallocated` event naming the same old ID, a predecessor creation event, a new lifetime allocated at the realloc event's sequence, and an old lifetime in the **same PID**, allocated before and freed at that event's sequence. Explicitly conflicting `Allocated` events, different recorded old IDs, event/lifetime PID, direction, sequence (including PID-local raw-vector order), allocation type, or **predecessor self-links** are contradictory **regardless of global history completeness**. The approved engine's distinct glibc `realloc(ptr, 0)` terminal-free event can be `Reallocated`, same old/new ID, NULL address and zero size; it ends an existing lifetime and is explicitly excluded from *creation* evidence. Its PID/sequence/free boundary remain validated. It is **not** an allowed predecessor self-link or a new allocation. Validation also checks **all explicitly linked raw realloc events**, including predecessors of linked blocks, for PID, sequence, lifetime direction and boundary contradictions (`REALLOC_EVENT_ORIGIN_CONTRADICTORY`). A linear visited-set walk of recorded block predecessor edges rejects cycles even if optional lifetimes/events are missing. Nonexistent old identities receive existing `REALLOC_ORIGIN_UNRESOLVED`; missing event, lifetime, predecessor sequence/free boundary, or legacy optional evidence yields `REALLOC_LINK_UNVERIFIED` unavailable (and never definite); multiple compatible creation events yield `Ambiguous` confidence, not a chosen first match. A failed realloc cannot act as a successful new lifetime. No address equality is used: in-place and moved reallocs share the same ID/sequence contract, and a later malloc at a freed address does not become a predecessor.

`heap(id).realloc_confidence` can be **Definite only** with corroborated creation-event/lifetime evidence **and** existing TP-6 `identity_confidence=Definite` (verified complete observed-PID history). Corroborated links in partial/legacy scope are only `Candidate`. Without corroboration the result is `Unavailable`, `Ambiguous` or `Contradictory` as appropriate. `old_id` and `old_lifetime` remain the original borrowed raw record references for investigation, not certified joins by themselves. Foreign `EvidenceRef` rejection and TP-7 `HeapIntervalEvidence::allocation()` inherit the same qualified result. One validation pass builds ephemeral maps for creation events of **only linked allocations and their recorded predecessors** and uses a linear-time cycle walk over linked blocks; these are not permanent indexes/graphs. Individual `heap` lookups use existing per-allocation indexed event positions, not a full-history scan.
