# Stage 1 final integrated audit — C source to validated semantic evidence

## Freeze decision

**A — Approved: freeze Stage 1 under its explicitly bounded V2.2 evidence contract.** This is an independent, read-only integration audit of the current Trace Engine → exported schema-v2 JSON → Trace Parser → `validated_semantic()` → read-only public-API consumer. It supersedes neither the historical conditional *parser* TP-8 finding nor its subsequent repair: the original fabricated-realloc-predecessor failure is now independently reproduced against a **new** engine trace and is reported contradictory, not definite. No new release-blocking false-certainty case was found in the tested scope. Approval is **not** a statement of complete process-tree coverage, a sound sandbox, lifetime identity from a pointer address or an independent Valgrind run, AST execution proof, or a bound on already assembled trace RAM. Stage 2 and architecture work have not started.

**Inputs:** `docs/trace-engine-v2.2-release-closure.md`, `docs/trace-parser-v2.2-final-audit.md` (historical B), `docs/trace-parser-v2.2-repair-f01.md` (repair A), TP-5/6/7, `docs/v2.md`, `docs/trace-parser.md`, and the current production implementation. All pre-existing uncommitted work was preserved. The only new repository artifact beyond this report is the **audit-only, read-only** public-API example `examples/stage1_public_consumer_audit.rs`. There are no production code changes, suppressed assertions, parser policy changes, or Stage 2 implementation changes from this audit.

The explicit `--config /tmp/cte-stage1/caller-config.json` sets `limits.max_caller_frames=3` for `recursion-callers`; the last CLI arguments are the fixture's program arguments after `--` for fork cases. GCC/GDB/Clang/Valgrind were available. `compile-error` deliberately exits 2 and still emits a valid failure trace; the other 15 corpus invocations exit 0. `/tmp/cte-stage1/raw_oracle.py` compared **separately decoded raw JSON to the actual JSONL records** for all 16 corpus files: 16/16 pass (`raw-oracle.log`). It asserts schema version, original instruction positions/event IDs, checkpoint references, ordered stop IDs, recorded gaps/attempted count, PID-local heap sequence, and—except for the deliberately capped journal—each journal instruction and allocation against the final records. In a two-event-PID fork, raw journal allocation IDs are **PID-local**, while final JSON IDs are deliberately widened to `(pid << 32) | native_id`; the oracle checked this explicit transformation, not raw numeric equality. The capped journal is 1,961 bytes, not a reconstructable complete trace. There is no silently synthesized missing event or shortcut from an observed PID list to all descendants. The parser's *own* independent TP-8 traversal probe traversed every instruction event (including all **3,143** heavy events), checked raw borrowed positions and bounded pages and found all 16 structurally sound; expected crash, step limit, incomplete ACK, capped journal and compile failure are correctly marked **partial** (`/tmp/cte-stage1/parse-probe.log`). Normal optional `SANITIZER_REPORT_UNRECORDED` and `HEAP_EVENT_ADDRESS_UNRECORDED` findings are not structural corruption.

An independent native `gcc -g -O0 -fno-omit-frame-pointer` / `gdb -nx -q -batch` at `phase8b_defined.c:15` produced `sum=10`, `*alias=7`, heap `[17,19,23]`, global `41`, and caller `main` (`native-gdb.log`). The live engine line-15 stop reports `sum="10"`, valid `raw_bytes_hex="0a000000"`, and a global `41` with bytes `29000000`. The recursive program's native GDB breakpoint also independently shows `recurse(value=3)` called by `main` (`native-recursion.log`); the *engine* captures 45 caller-frame records in its separately configured run. Different executions' numeric addresses, PIDs, stop IDs and allocation IDs were **not** joined. AST-off omits optional metadata; AST-on has expressions and DWARF types, which remain **static candidates**, never proof that a call executed. Byte readability does not prove initialization.

## Stage 2-shaped integration test — public APIs only

`examples/stage1_public_consumer_audit.rs` opens each JSON via `TraceStore::open`, calls `validated_semantic()` **once**, checks report soundness/partiality and scope, and uses public `checkpoint_summary`, bounded local/global/caller variable pages, frame activation, memory/pointer qualification, bounded checkpoint instruction/heap-interval pages, session diagnostics, optional source-expression page, Valgrind diagnostic pages and trace-scoped heap reference/event pages. All requested ranges are half-open, explicitly capped at `MAX_CONSUMER_PAGE=128`; skipped unavailable optional evidence is reported as unavailable, not fabricated. It never treats containment (`address_candidate`), a static source match, or an independent diagnostic as allocation provenance; `primary_allocation_id` stays `None`. This is a throwaway **consumer oracle**, not a Stage 2 implementation. Release executable run against **all 16** fresh JSON documents: 16/16 succeeded, including zero-snapshot compilation failure, caller frames, incomplete fork, 3,143-event heavy trace and AST-off (`/tmp/cte-stage1/consumer-*.log`). The consumer samples the first six checkpoints per trace; the separate TP-8 probe traverses *all* instruction events. Existing TP-7 regressions independently verify 300 events and 1,024 variables across explicit 128-entry pages; this real heavy fixture has only a few events per checkpoint, so it does **not** prove 128 events at one real stop.

## Reliability, resource and compatibility boundaries

- **Failure paths:** compile failure has a diagnostic but zero phantom stops; crash retains crash report; forced sanitizer and independent Valgrind retain separate tool stages. Step-limit and capped journal retain incomplete scope, not a complete-history claim. The incomplete fork has `heap_history.complete=false` and a missing event-PID ACK; `fork-silent` can have `complete=true` only for its **observed PIDs + followed inferior**, while `unobserved_process_coverage="unknown"` in all fork runs. The incomplete fork also had a failed Valgrind stage; that stage is not promoted to primary-run heap certainty. The tested bounded subprocesses terminated; a process listing after capture showed no remaining audit inferior/GDB. Existing suite regressions additionally cover cancellation, timeouts, truncated reads, malformed/torn journals, output and resource enforcement; this bounded live corpus does not independently reproduce every failure type.
- **Resource limits, kept separate:** `--max-trace-bytes 2048` bounds JSONL capture (1,961 bytes), truncates recording and yields partiality, **not** the 22,883-byte exported JSON. A separate `--max-json-export-bytes 8192` engine run exited **1** with `max_json_export_bytes exceeded`, **no JSON output** (`export-cap.err`); it was not parsed or counted as successful. That limit bounds *each serialized export*, not already assembled trace RAM or parser RSS. The parser's input, record-count and 128-item page bounds are separate; oversize page rejection is exercised in TP-7's suite. The export cap does not imply a heap allocation cap or a no-OOM promise.
- **Compatibility:** freshly reran all six **actual** supported `examples/v21_{normal,loop,heap,crash,dual,bounded_infinite}.json` through the production parser probe: 6/6 sound (`compat-v21.log`); legacy missing pointer provenance remains unavailable, not invented. `v21_manifest.json` is a manifest, not a trace. Four pre-V2.1 `examples/v2_*.json` with removed limit fields remain a previously documented ingestion limitation, not new support. Schema v2, canonical `Arc<DebugSessionTrace>`, position-only indexes and borrowed records are unchanged. JSONL parsing does **not** reconstruct final reports or a full trace.
- **Release-profile observations:** three independent runs of the existing TP-3/6/7 benchmark on **these** `defined` (461 KB) and `heavy` (3.337 MB) traces (`bench-{0,1,2}.log`): median typed parse ~8.27 / 47.85 ms, index build ~0.264 / 1.130 ms, once-only TP-6 validation ~0.263 / 0.555 ms, RSS after index ~5,076 / 17,248 KiB. The index estimate on the heavy trace is 28,369 bytes, **not total RSS**. TP-7 summary median ~55 / 89 ns, bounded checkpoint-event page ~236 / 259 ns; synthetic 128-variable page 24–34 µs per run. Per-query benchmark allocations and TP-7 summary live-byte delta were **zero**; validation is intentionally once-only and *does* allocate. Timings are instrumentation/host dependent; the TP-8 raw-JSON probe holds a second decoded representation and its ~41 MB heavy RSS is **not** index RSS. Three-run logs include host-scheduling variance, not a claimed speedup. Fresh 12× load/validate/drop with four shared cloned readers per cycle on heavy: post-drop RSS 27,372 → 31,684 KiB, stabilizing ~31,680 KiB after allocator warmup (`cycles-heavy.log`); post-drop RSS is not a live-byte measurement or a proof of arbitrary-duration leak freedom. Engine `/usr/bin/time` peak RSS ~152–153 MiB on representative captures is **not** a parser memory guarantee. No new persistent index or record copy was added in this audit.

## Verification, freeze contract and residual risk

After the last audit-example code edit, all **five required commands passed**, with logs `/tmp/cte-stage1/final-{check,fmt,clippy,release,tests}.log`:

```
cargo check --all-targets
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo build --release
cargo test --no-fail-fast -- --test-threads=1
```

Serial suite **383 passed, 0 failed, 0 ignored across 22 targets** (including the doctest); no reported environmental skips. `git diff --check` passed. The audit-only example initially needed a Rust temporary-lifetime semicolon and was fixed and rechecked before this final five-command run; no production code or assertions were relaxed. The original TP8-F01 regression remains preserved. The user worktree, including extensive earlier uncommitted Trace Engine/parser work, was not reset or committed.

**Freeze contract for downstream work:** load compatible schema, call `validated_semantic()` explicitly and heed its structural/partial findings; use borrowed, same-trace scoped `EvidenceRef`s and explicit ≤128 pages; retain source/stop/PID/execution-domain qualifications. Report unavailable evidence as unavailable. In particular never turn pointer containment into provenance, a source candidate into executed expression, cross-run Valgrind diagnostics into a primary allocation ID, or observed-PID completeness into all-descendant coverage. Unsupported historical files, silent forks, incomplete/missing transport or legacy evidence, and unbounded assembled-trace RAM remain acknowledged risks. **No blockers within this qualified Stage 1 scope. Verdict A — Approved for the Stage 1 freeze; Stage 2 remains separately authorized work.**
