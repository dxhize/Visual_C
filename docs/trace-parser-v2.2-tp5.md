# TP-5 — Trace Parser V2.2 compatibility and validation

**Status:** parser-only repair completed; TP-6 semantic evidence layer not started. Read with `docs/trace-parser-v2.2-audit-tp4.md` and the Trace Engine release-closure scope. Production Trace Engine behavior, schema v2, JSONL record-only parsing, `TraceStore::from_trace`'s schema-only gate, canonical `Arc<DebugSessionTrace>`, position-only TP-2 indexes, and borrowed views were not changed.

## Root causes and changes

1. `src/trace_parser/validation.rs::validate_pointer_reference` rejected definite heap IDs for three uncertain statuses but **omitted `address_only`**. More importantly, `validate_caller_frames` returned immediately when no caller frames were captured, skipping *all* frame-0 and global pointer validation in the common case. The validator now checks pointers even with no callers, and no explicitly recorded status (address-only, ambiguous reuse, incomplete history, known freed, or unknown future status) can authorize a definitive heap ID. A non-heap kind cannot claim one; disagreement between a definite ID and a numeric-address candidate is separately reported. A missing legacy status with a heap ID remains importable but now receives `UnavailableEvidence:POINTER_HEAP_PROVENANCE_UNRECORDED`; absence is **not** parser proof of origin.
2. Heap-history validation checked gaps but never inspected V2.2 process annotations. `HeapProcessScope<'_>` in `src/trace_parser/views.rs` is a borrowed, typed **recorded scope**: `Unknown`, `VerifiedObservedPidsOnly { observed_event_pids, followed_inferior_pid, observed_history_complete }`, or `Unsupported`. `TraceStore::heap_process_scope()` centralizes parsing of the single V2.2 scope string; `heap_history()` borrows the original record. `validate_deep` rejects unsupported scope/unobserved-coverage strings, duplicate/zero observed PIDs, retained events whose PIDs are missing from an explicitly declared observed list, and an explicit `complete=true` contradicted by recorded sequence/transport/retention losses. Missing optional process metadata remains unknown or unavailable. `"unknown"` is the **only** supported annotation for unobserved processes; there is no descendant census.
3. On-demand borrowed `TraceStore::type_registry()` and `evidence_fusion()` accessors expose the existing trace-local metadata without copying registries. Existing AST declaration/expression lookups, caller-frame/byte and evidence refs, heap-lifetime/realloc queries and diagnostic report access remain unchanged. No new eager metadata index was justified: TP-5 introduces no repeated ID-join workload requiring one; source lookup remains bounded linear (max 2048 recorded declarations). The existing position-only index set was untouched. No inferred AST execution, pointer origin, or Valgrind/primary-run allocation identity was added.

**Validation costs:** removing the no-caller early return initially caused per-snapshot identity-map allocations in common traces. Measured `validate_100` on 22 MB/1000 snapshots rose from TP-4's ~9.1 ms to ~89.5 ms. The final implementation avoids building that map unless a pointer actually cites a recorded variable identity, and skips no-caller snapshots with no pointer targets. Final measurement is ~11.6 ms/100 on the same trace, with frame-0/global pointer checks still active. Callers and variable-identity references still receive the full association and extent checks.

Independent replay of the TP-4 *real-trace* mutations (`examples/trace_parser_tp4_audit.rs` against `/tmp/cte-tp4/{reuse,fork-silent}.json`): previously both said `structural=false` (`/tmp/cte-tp4-adversarial.log`); now address-only + definite ID gives `POINTER_HEAP_PROVENANCE_CONTRADICTORY`, and false descendant coverage gives `structural=true` (`/tmp/cte-tp5-real.log`). Other live V2.2 samples—AST on/off, recursion with 45 caller frames, reuse/realloc, crash, partial log, observed child, silent child, missing child ACK and source-large—remain structurally sound; crash/partial/missing-ACK cases still show **partial coverage**, not fabricated completeness. ## Evidence/coverage contract for consumers

| Observation | Validated interpretation | What is **not** established |
|---|---|---|
| `address_match_allocation_id`, including active block, freed address, reused address, ambiguous reuse or incomplete telemetry | Candidate for a *numeric* address; retain status and candidate separately | Origin, lifetime identity, or a definite allocation link from containment |
| `allocation_id` with explicit uncertain/unknown provenance status, or non-heap target | Structural contradiction (`POINTER_HEAP_PROVENANCE_CONTRADICTORY`) | Do not repair by silently erasing the ID or promoting the candidate |
| Definite ID and different numeric-address candidate | Structural contradiction (`POINTER_HEAP_ADDRESS_MISMATCH`) | No cross-run address join |
| Absent optional pointer status with a recorded heap ID | Legacy/unknown provenance, `POINTER_HEAP_PROVENANCE_UNRECORDED` unavailable finding, not structural corruption | A proof of identity; the parser does not reconstruct missing provenance |
| `heap_history.complete=true` with `process_scope=verified_observed_pids_only` | Only verified observed-event PIDs plus known followed inferior, subject to `validate_deep`; observed history may be complete while other processes remain unknown | A count of children, complete descendant coverage, or child snapshots |
| Missing process scope or no heap history | `HeapProcessScope::Unknown` even when legacy `complete=true` | Complete descendant coverage |
| `unobserved_process_coverage=unknown` | Unobserved processes remain unknown in parent-only, observed-child and silent-child runs | Proof that no silent fork occurred |
| Child logs without terminal ACK / known transport loss | Observed history incomplete (`HEAP_HISTORY_INCOMPLETE`), not necessarily structurally corrupt | Complete allocation history |
| Valgrind `source_site_candidates` | Independent source-site candidates; retained via borrowed report | Definitive `related_allocation_ids` or same-execution primary provenance |

`TraceStore::open`, `from_json_bytes`, and `from_trace` succeed on **deserialization/schema compatibility**, not deep structural soundness. Before a consumer trusts a reference, call `validate_deep()` and inspect structural findings *and* coverage/unavailable findings; before claiming semantic confidence, additionally inspect evidence status, process scope and source/cross-run origin. `heap_process_scope()` reflects recorded annotation and is **not** a validator; `Unsupported` or an unsound report must not be treated as complete evidence. Borrowed `EvidenceRef` identity remains trace-scoped: references from unrelated stores cannot be resolved as if from the same execution. `max_json_export_bytes` limits the serialized engine document, not already assembled trace memory or parser RAM.

The next *completed* serial run recorded **one** `tests/integration.rs::valgrind_flags_use_after_free` failure: its 12-second pipeline deadline expired in Valgrind, leaving truncated XML, with 11 other integration tests passing (`/tmp/cte-tp5-tests-final2.log`). The unchanged test passed alone in 6.38 s (`/tmp/cte-tp5-valgrind-rerun.log`); the subsequent complete serial suites passed 361/361, including the final run after adding the missing-provenance unavailable finding. No parser code path runs during that test, and the failure was not suppressed or counted as a clean run.

**TP-6 handoff:** use validated, trace-local borrowed records and status/coverage findings; preserve source-site candidate vs allocation identity, attempted vs retained event positions, and followed-inferior vs all-fork scope. Do not infer executed AST calls, complete multiprocess history, definitive origin from address matches, or cross-run Valgrind allocation identity. No semantic evidence layer, all-process tracing, whole-trace memory limit, or historical pre-V2.1 compatibility expansion is provided by TP-5.
