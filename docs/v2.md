# V2 recording contract

## Architecture and compatibility

The existing GCC pipeline, MI tokenizer/parser, allocation runtime, native
Valgrind XML parser and sanitizer parser are reused. `trace.rs` coordinates
stages and the stop loop; `recorder.rs` captures and journals observations;
`processor.rs` validates references and reconstructs recorded register deltas.
`supervisor.rs` owns monotonic budgets and cancellation-safe child groups.

The wire schema is **2**. Existing fields (`snapshots`, `heap_events`,
`execution_status`, reports, metadata) remain. New fields include:

- `execution`: canonical typed program outcome, exit code, signal, crash PC.
- `stage_results`: independent compiler/debugger/Valgrind/sanitizer/tracker health.
- `tracing_configuration`, `coverage`, `storage`, `profiling`.
- `execution_limits`: the effective limits used for the recording.
- `disassembly_table`, `instruction_events`, `initial_registers`, `trace_gaps`.
- `source_checkpoints`: indices into `snapshots`, not duplicate memory objects.
- `allocation_lifetimes`: stable IDs, native event sequence boundaries, raw
  caller PCs, module and explicit resolved/unresolved status.

Legacy fields are not renamed: for example `execution_status: "timeout"`
corresponds to `execution.outcome: "timed_out"`. Recording/output caps use the
legacy `step_limit_reached` alias; `execution.outcome` distinguishes output
exhaustion. A Valgrind failure does not change the program outcome.
Old documents deserialize with default V2 extension fields; absence of those
fields is **not evidence that instruction recording occurred**.

Consumers can continue using legacy snapshots, or navigate V2 references.
Validate with `processor::validate`. In journal-only mode load instruction
records from the journal: an empty resident array does not mean zero events.

## Timeline semantics (avoid the PC off-by-one)

At stop S, GDB's PC identifies the **next** instruction. The recorder:

1. Observes that address/source/thread.
2. Sends `-exec-step-instruction` and separately awaits async `*stopped`.
3. Emits an event containing the **pre-attempt** address and the observed
   `next_address`, post-attempt stop reason, registers and selected memory.

`event_id` is zero-based, ordered, and counts **attempts**, not just successful
instructions. `outcome` is:

- `completed`: GDB reported the single-step completion.
- `faulted`: a synchronous fault signal stopped at the attempted PC.
- `interrupted`: another signal interrupted execution.
- `unknown`: no sufficient completion evidence, including failed/missing stops.

Breakpoint stops are conservatively not treated as proof of completion.
No event is generated by disassembly alone.

`stop_id_before/after` connect events to actual observed stops; an absent
after-stop ID means no response was observed. Snapshots contain
`observation.stop_id`, PC, thread, PID, origin, errors, and
`instruction_position`: the number of recorded attempts before that snapshot.
Position 0 is before the first attempt; position N is after N attempts.
`checkpoint_id` references the most recent source checkpoint, not a claim
that its memory still equals the current memory.

Source checkpoints occur at initial entry, file/line/function changes,
entry breakpoints, and faults. Repeated loop iterations remain separate
events. Same-line function changes are preserved. A native exit without a
source frame is represented by the execution outcome and ending gap, not an
invented variable snapshot.

## Coverage

The supported instruction scope is **user code**. Frame origins are
`user_code`, `instrumentation_runtime`, `system_library`, or `unknown`.
Allocator/runtime frames do not become ordinary source checkpoints, but
allocation events still enter the timeline before the next checkpoint.

Gaps identify startup and each interval skipped by source stepping or
`finish`/`continue` through excluded code. A gap has a boundary position and
observed endpoint PCs; its unknown instruction count is never guessed.
User entry-address breakpoints (bounded discovery of 128 functions) make
callbacks such as `qsort` observable inside skipped library calls. Missing
DWARF mappings, capped discovery and native debugger limitations can still
limit coverage. No all-libraries or all-process instruction-capture mode is
claimed.

The backend reports GDB **all-stop** mode. Multiple observed threads mark
instruction coverage incomplete: this version records selected-thread steps,
not a complete interleaving. All-stop does not freeze external processes
sharing memory. Fork children are not instruction-traced; allocation events
may still arrive from them. Entry capture does not trace the dynamic loader
before main.

## Registers

GDB register names/numbers and target architecture text are retained; no
x86-specific register indices are hard-coded. Initial and periodic full
observations establish delta bases. For each step, a full native GDB query
is compared with the previous **observed** register set for that thread.
Only changed values are serialized between checkpoints. Missing values
explicitly invalidate older ones; they never become zero.

The default full-checkpoint interval is 256 attempts. A gap forces the next
observation to be full. A capped or failed register read cannot establish
a valid new base. `processor::replay_registers` seeks the latest valid full
checkpoint and applies deltas; it errors rather than returning stale values
as exact when observations are missing. It operates on resident events;
journal readers can implement the same rule incrementally.

Disassembly is collected in bounded 128-byte windows and cached per loaded-image epoch, with runtime addresses,
native bytes/text, function and module mapping. Library load/unload
notifications invalidate the address cache without invalidating old table
IDs. ASLR addresses are never replaced with fake addresses.
Self-modifying/JIT code is **unsupported**; immutable code is a requirement
for cache fidelity.

## Memory and value validity

Rich memory is captured at source checkpoints while stopped. Individual
values distinguish `valid`, `unavailable`, `unreadable`, `optimized_out`,
`truncated`, and `not_captured`. Here “valid” means the debugger returned
an observation, **not** proof of C initialization or absence of undefined
behavior. No uninitialized state is inferred from byte patterns.

Pointers retain their exact `address` (pointer storage) and `points_to`
(stored target). `target` classification uses recorded extents/symbols:
null, heap (ID/base/offset/active), known stack variables, globals/statics,
or unknown. Code/stack/unmapped classifications can additionally use actual
`/proc/PID/maps` evidence; failure to read mappings stays unknown.
Extent matches describe address evidence, not pointer provenance: address
reuse cannot prove whether a pointer originated from an old object.
Freed-block bytes are historical and do not reactivate the allocation.
`observed_at_stop` identifies when each heap byte capture was made.

Variable identities use per-thread activations and native DWARF lexical block
bounds/declaration metadata when GDB's embedded Python is available. These
identities do not depend on the current storage address. Shadowed symbols are
read through GDB's actual `Symbol.value(frame)` rather than pairing every
`&name` query with the innermost address. If introspection is unavailable,
storage-based fallback IDs are explicit; ambiguous associations omit addresses
instead of guessing. No Python code executes inside the C inferior.
Raw DWARF DIE IDs and non-top-frame local inspection remain unsupported.
Storage classifications use observed Linux mappings and remain unknown when
evidence is insufficient.
Global/file-static symbols are discovered through MI, with file qualification
for ambiguity. Function-local statics become persistent inspection expressions
once observed in their function; `--global 'function::name'` can request them
earlier.

Variables, heap and globals share the source snapshot byte budget. Optional
`--memory-region '&global_value:4'` records bounded **actual reads after each
instruction stop**, with expression, resolved address, bytes and status.
Without such an observation, instruction-position memory is **last-known**
from an earlier checkpoint or unavailable, never exact by implication.
No assembly interpretation or synthetic write reconstruction is used.
Inspection function calls are disabled; side-effect expressions are rejected.

Heap event ordering is ingestion order: drain telemetry while the inferior
is stopped, then read source state. A snapshot records the number of
ingested heap events. Native sequence numbers remain per-process; IDs widen
with PID when multiple processes are observed. Realloc-in-place preserves an
ID; moving realloc retires/links objects; failed realloc preserves the old
object. Linker wrapping does not see internal allocations in shared libraries.

Allocation caller PCs are retained even if resolution is skipped. For
ELF64 little-endian PIE, `/proc/PID/maps` and PT_LOAD headers establish the
load bias while the inferior is alive. Batched addr2line queries use
image-relative PCs, then map results back to raw PCs. Unsupported executable
formats, unknown modules and absent symbols stay unresolved.

## Deadlines, processes and stage health

`--timeout` starts before tool probes and bounds the entire pipeline via
`Instant`. Compiler/debugger/analysis budgets are each clamped to the same
deadline. Every GDB command—including snapshot queries—checks it and the
command cap. A successful `^running` acknowledgement is **not** a stop.
Late async tokens cannot resolve command oneshots. On response timeout the
session is poisoned rather than risking attribution of late streams.

A missing-stop wait before the overall deadline is a debugger failure with
an operation reason, **not proof of an infinite loop**. Expiring the global
or stage deadline is a timeout. After expiry, new analyses are skipped.
Each stage records timing offsets/duration, native exit code when available,
failure reason, output completeness and partial-results availability.
Skipped stages have no fictitious start/exit timestamps.

GCC, addr2line, Valgrind and sanitizer processes have cancellation-owned
groups and concurrent bounded pipe drains. Descendants cannot hold pipes
open forever. GDB and its separately grouped inferior are both terminated;
the interrupt request has a 100ms bound before forced termination/reaping.
Allow up to two seconds for process cleanup after a deadline.

SIGINT/SIGTERM during collection request supervised cancellation. Pending
debugger/process waits wake immediately, cleanup runs, and useful partial
JSON is returned with `interrupted`/`cancelled` metadata. Linux subreaper
ownership allows specific orphaned descendants to be reaped without stealing
other concurrently owned children's exit statuses. Abrupt SIGKILL/power loss
cannot run normal finalization; recover complete journal records where possible.

Inferior address-space/CPU/file/core limits are set with Linux `prlimit`
at the initial stop—not on GDB itself. Startup before that stop is outside
these inferior-only rlimits. Diagnostic runtimes have CPU/file/open-file
limits, **not** an ASan-breaking small virtual-address cap. `RLIMIT_NPROC`
is not used: it is per-user, not per-tree. A delegated cgroup adds
best-effort tree memory/PID control. Without one, descendants that deliberately
escape their group are not guaranteed contained.
These mechanisms are **not a security sandbox**.

Malformed/missing Valgrind XML never produces a successful empty report.
Complete native `<error>` records can be recovered from a truncated file;
`output_complete`, `summary_available` and `parse_error` disambiguate absent
summary data from zero totals. `observed_summary` and
`observed_leaked_bytes`/`observed_leaked_blocks` carry nullable native numbers.
Legacy integer fields keep defaults for compatibility: **a zero is not evidence
when its corresponding observed field is null**. Grouped native counters such
as `4,152` are parsed strictly rather than silently becoming zero.
The runtime is genuinely passive during Valgrind so its allocation table cannot
turn lost blocks into still-reachable roots. Sanitizers run independently,
never under Valgrind, and nonzero
exits without diagnostics are inconclusive. Sanitizer fallback is recorded
in metadata/notes. A native sanitizer diagnostic is labeled `reproduced` and
attached to a crash only when source-site evidence supports correlation;
otherwise it remains `diagnostic_observed`.

## Storage and budgets

JSON export streams directly to writers (stdout and optional file), avoiding
one enormous in-memory JSON string. `--journal file.jsonl` writes ordered,
independently parseable configuration, disassembly, register, checkpoint, gap
allocation and instruction records as execution proceeds. Existing journal files are
never overwritten. A finalized footer is synced on successful closure.
`storage.finalized` says whether collection closed, **not** whether execution
completed or coverage was complete.

`storage::recover` incrementally reads complete records and ignores a
crash-torn last line. `--journal-only` evicts dynamic instruction events from
resident output; the JSON index still contains tables and bounded source
snapshots. This is not a random-access binary/indexed storage format:
seeking a JSONL journal currently requires a scan.

Execution/event/storage limits terminate collection rather than silently downgrade
instruction fidelity. Per-read/inspection caps retain explicitly partial observations:

| Configuration | Default | Meaning |
|---|---:|---|
| `max_instruction_events` | 100,000 | attempted instruction events |
| `max_source_checkpoints` | 1,000 | source-state records; also clamped to legacy max snapshots |
| `max_gdb_commands` | 1,000,000 | all debugger queries and execution commands |
| `max_trace_bytes` | 128 MiB | serialized journal data budget (also counted without a journal) |
| `max_trace_memory_bytes` | 32 MiB | serialized resident-record accounting, not total Rust RSS |
| `max_register_snapshot_bytes` | 64 KiB | one register observation |
| `max_globals` | 32 | global/static inspection expressions |
| `compiler_timeout_seconds` | 30 | compiler stage, clamped to whole session |
| `debugger_timeout_seconds` | 30 | debugger stage, clamped to whole session |
| `analysis_timeout_seconds` | 10 | each analysis, clamped to whole session |

Legacy max steps counts source steps in source mode, checkpoint progression
in dual mode; instruction budgets are separate. Export formatting, compatibility
arrays, heap summaries and control metadata can exceed journal byte accounting;
the cap is **not** a hard final-JSON file-size or engine-RSS limit. Source
snapshots/static tables remain resident under their accounting caps even with
journal-only capture. More compact indexed storage and hard engine-RSS
supervision are future work.

## Configuration example

```json
{
  "source": "sample.c",
  "limits": {
    "timeout_seconds": 20,
    "debugger_timeout_seconds": 15,
    "max_instruction_events": 5000,
    "max_source_checkpoints": 500,
    "max_trace_memory_bytes": 16777216
  },
  "tracing": {
    "mode": "dual",
    "registers": true,
    "static_disassembly": true,
    "register_checkpoint_interval": 256,
    "memory_regions": [{"address": "&global_value", "size": 4}],
    "globals": ["function::local_static"],
    "discover_globals": true,
    "journal": "session.jsonl",
    "retain_instruction_events": false,
    "profiling": true
  }
}
```

Use expressions that exist in your own program. Relative source/include paths
are evaluated against the configured build working directory.
Configuration enums reject unsupported tracing modes; no silent fidelity downgrade.

## Validation and measurements

See `tests/v2.rs`, transport/parser unit tests, legacy integrations, and
[benchmark measurements](benchmarks.md). New coverage includes null writes
at the fault PC, both source and instruction infinite-loop deadlines, callbacks,
recursion, same-line functions, globals/statics, pointer-to-pointer links, PIE,
address reuse, moving realloc, missing source mappings, output caps, selected
memory, register replay, malformed/truncated records, GDB death and cleanup,
journal recovery, and instruction limits.

Validated on Linux x86-64 with GCC 16/GDB 18/Valgrind 3.27.
The runtime rejects targets without a 64-bit `unsigned long`; register schemas
use native GDB identities, and relocation normalization is ELF64 little-endian.
Other targets are not validated. No globally atomic cross-process snapshots,
complete multi-thread/fork instruction timeline, self-modifying/JIT fidelity,
all-library tracing, full lexical DWARF identity, or omniscient instruction
memory history is claimed.
