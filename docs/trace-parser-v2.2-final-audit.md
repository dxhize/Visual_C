# TP-8 — independent final Trace Parser V2.2 audit

## 1. Executive assessment and decision

**B — Conditional: one targeted parser repair is required before the final Stage 1 integrated audit.** On fresh Linux GCC/GDB/Clang/Valgrind V2.2 traces, TP-1–TP-7 preserve raw records, keep position/stop/PID/identity domains separate, and distinguish missing, partial, contradictory and independent-run evidence. Bounded pages and 3,143 **real retained instruction events** were exercised. However, an imported, fabricated **reallocation predecessor pointing to a different *existing* allocation** passes `validate_deep()` as sound, and `validated_semantic().heap(1).realloc_confidence` becomes **`Definite`**, even though the original recorded event says allocation 1 was *allocated*, not reallocated. This is false certainty in a supported semantic consumer query. The engine-produced trace was sound; the failure occurs only after an import mutation. No production repair was made in this primarily read-only audit.

**Severity: P2, release-blocking for the semantic link contract.** The smallest repair is to validate an explicitly recorded `heap_state.realloc_from_id` against a corresponding recorded realloc event and PID/identity/sequence/lifetime where reliable, reject cycles/self-links and disagreement in a verified complete history; in partial/legacy history, report unavailable rather than infer a definite predecessor. TP-6 `realloc_confidence` must not become `Definite` solely because both lifetimes exist under a globally complete flag. Add a failing-before/passing-after regression for the preserved import, and repeat all verification before changing this verdict. `from_trace` **must remain schema-only**; this is a deep-validation/confidence defect, not a request to make ingestion reject partial traces. The bounded TP-8 audit harness is in `examples/trace_parser_tp8_{audit,mutate,cycles}.rs`. No TP-9, Semantic Engine, frontend, new tracing capability, Stage 1 integrated audit or architecture work was performed.

## 4. Adversarial imports and reproducible defect

Deterministic one-field/one-record mutations of the fresh engine traces (16 cases), full repro inputs `/tmp/cte-tp8/mutations/*.json`, exact outcomes `/tmp/cte-tp8/mutations2.log`. Parsing a mutation is deliberately **not** proof of soundness. `address_only` or `ambiguous_reuse` + definite ID produces `POINTER_HEAP_PROVENANCE_CONTRADICTORY`; false all-process completeness `HEAP_PROCESS_COVERAGE_UNSUPPORTED`; declared complete history with losses `HEAP_OBSERVED_COVERAGE_CONTRADICTORY`; omitted observed PID `HEAP_EVENT_PID_UNOBSERVED`; duplicate heap identity `HEAP_STATE_ID_DUPLICATE`; duplicate DWARF/AST IDs `DWARF_DUPLICATE_ID` / `AST_DUPLICATE_ID`; nonexistent instruction checkpoint `CHECKPOINT_REFERENCE_INVALID` plus engine corruption findings. In each unsound case the TP-6 checkpoint and descendant confidence are `Contradictory`. A missing realloc predecessor ID is `REALLOC_ORIGIN_UNRESOLVED` **unavailable** (not claimed definite); removal of legacy process scope stays unknown; removal of optional AST while leaving explicit AST variable references correctly reports structural invalid links. Unsupported version and wrong-type required snapshot field fail at ingestion. Reversed/past-end page queries return `InvalidRange`, over-limit TP-7 pages return `LimitExceeded`, foreign refs are rejected in TP-6/7 focused tests. Crash and step-limit traces remain importable as **partial**, not corrupt. Complete journal: 350 records; torn final line: same 350 records and `torn_tail=true`; a newline-terminated malformed payload raises `MalformedJournalRecord` at line 351. These are typed import failures, not journal reconstruction.

**Confirmed release blocker TP8-F01:** Start from the 460,442-byte fresh `small.json`, replace only `/heap_state/0/realloc_from_id` with `/heap_state/1/allocation_id` (=2). Raw event for allocation 1 is `Allocated`, `old_allocation_id=null`; allocation 2 is the real realloc successor *from* 1. Import now falsely says allocation 1 came *from* 2, creating a contradictory cycle. **Actual:** `validate_deep().is_structurally_sound()=true`; `validated_semantic().heap(1).old_id=Some(2)`, `realloc_confidence=Definite`. Fresh unmodified trace's `heap(1).old_id=None`. Independently inspected raw JSON confirms this disagreement; no GDB address similarity is involved. The single-field delta/reproduction commands are preserved in `docs/trace-parser-v2.2-tp8-reproducer.json`, full changed file `/tmp/cte-tp8/mutations/realloc-fabricated-existing.json`, engine baseline `/tmp/cte-tp8/small.json`. A separate self-link mutation is also incorrectly **structurally sound**, though `heap(1).realloc_confidence=Contradictory`; this confirms the missing validator check but not the same false-semantic-confidence severity. **Affected:** `validate_deep`/`ValidationReport`, `ValidatedSemanticView::heap` and `heap_reference`, TP-7 `HeapIntervalEvidence::allocation` / any consumer trusting heap predecessor confidence. A mere generic `Contradictory` downgrade for all structurally bad traces cannot protect this case because validation says sound. Do not rely on a clean report or definite realloc-confidence for untrusted imported realloc links until repaired.

## 5–6. Release performance, resources and concurrency

Three **separate, sequential release processes per input** (`/tmp/cte-tp8/bench-{small,medium,instruction-heavy}-{0,1,2}.{log,time}`); table medians. The TP-8 oracle retains an independent `serde_json::Value` as well as the typed model, so its RSS includes **two representations** and must not be mistaken for isolated index size. Typed-parse time excludes disk read/JSON Value decode; `from_trace` index timing excludes deserialization; `validate_us` includes one `validated_semantic()` call; `traverse_us` includes the independent raw JSON filter **for every checkpoint**, which is intentionally quadratic and is **not** TP-7 traversal latency. OS RSS and timings are workload/allocator/host dependent. The engine's JSON export limit only bounds serialized documents, not already assembled trace or parser RAM.

| AST-on small | 460,442 / 45 / 157 | 5.207 | 0.245 / 16,048 | 8,116 / 8,648 | 0.207 | 2,315 |
| recursive medium | 147,016 / 26 / 69 | 1.898 | 0.134 / 5,625 | 5,032 / 5,508 | 0.056 | 342 |
| **new instruction-heavy** | 3,333,094 / 900 / **3,143** | 37.755 | **1.103 / 28,369** | **40,780 / 42,688** | **0.400** | 292 |

The native three-run TP-3/TP-6/TP-7 benchmark on the new heavy trace (`/tmp/cte-tp8/existing-bench-heavy-{0,1,2}.log`) avoids retaining the independent raw Value: ~**16,944 KiB** process RSS after TP-6 validation in one run, ~39.1 ms typed parse, ~1.04 ms index, TP-2 bounded instruction range ≤16 **12.4 ns**, 900-checkpoint+events traversal **~184 µs**, TP-7 summary **~60 ns**, checkpoint event page **~247 ns**, TP-6 once-validation **~0.49 ms** (representative run; full three-run logs are cited). All serial query measurements reported **zero allocations** (benchmark counts allocation calls); summary creation had zero live-byte delta; the concurrent 4-reader microbench includes thread creation/benchmark allocations and is **not** a per-view allocation count. TP-7's existing synthetic 128-variable page processed **all 128** rows at ~22 µs; eight pages process 1024 variables at ~180 µs; oversized page rejected at ~15 ns, zero query allocations. All reported quantities are observations, not throughput guarantees. The new heavy trace's checkpoint page contains at most four events; large-event traversal is separately measured through the TP-2 range and all checkpoint pages.

Fresh-process twelve sequential independent `TraceStore::open` / validate / drop cycles with four cloned store readers per cycle, 20 reads per reader, on small and instruction-heavy (`/tmp/cte-tp8/cycles-{small,instruction-heavy}.log`). All 24 cycles passed sharing and read assertions, no deadlock or panic. Heavy initial RSS baseline **2408 KiB**, after-drop 27,404 KiB (first) → 31,724 KiB (twelfth), plateauing after allocator warmup; small 2440 → 6604 → 7232 KiB. Post-drop RSS does not equal live trace bytes: allocator and OS retain pages. No monotone per-cycle growth of comparable size to the trace was observed after warmup; twelve cycles do **not** prove leak-freedom for arbitrarily many loads or machines. Cloned readers use the same canonical owner and shared position indexes; independent `open`s intentionally create distinct `Arc` identities.

## 7. Verification and failures investigated

Focused parser integration: `cargo test --test trace_parser --test trace_parser_indexes --test trace_parser_views --test trace_parser_semantic_tp6 --test trace_parser_consumer_tp7 -- --test-threads=1` **64 passed, 0 failed, 0 ignored** across five test targets (`/tmp/cte-tp8/focused.log`: 13+10+15+7+19, different binary execution order); no GCC/GDB/Clang/Valgrind environmental skip lines. Direct fresh engine → parser audit probes passed for seven cases and forced sanitizer. Adversarial harness completed and **demonstrated TP8-F01**; its expected-failure reproducer is **not** counted as a passing safety regression. One initial CLI fork probe mistakenly placed `-- observed` before later CLI options, redirecting output incorrectly; rerun correctly placed program arguments last and produced the 2-PID trace. The first attempt to regenerate the instruction-heavy trace with the preserved fixture reused an existing audit JSONL path; the engine explicitly reported `gdb phase failed: io error: File exists (os error 17)` and emitted a **0-event execution_failure** trace. The audit-owned old JSONL/output were removed, the command was rerun, and only the successful **3143-event step-limit trace** was used in the final three-run benchmarks. This failed generation was not counted as a successful parser workload. The first compatibility-probe glob accidentally included `v21_manifest.json` (not a trace) and panicked; the explicitly listed six-trace rerun passed. Initial audit-example compile errors (calling `instruction_events()` where only `instruction_event/range` exist and treating `shared()` as a store clone instead of `Arc`) were fixed in the **audit harness only**, and verified by comparing to raw JSON and checking shared-pointer identity. The old pre-V2.1 four fixtures' expected ingestion failures are separate from full-regression failures. No production code was repaired or tests suppressed.

After the final audit-harness code edit, **all five commands passed**: `cargo check --all-targets`, `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo build --release`, and `cargo test --no-fail-fast -- --test-threads=1`. The completed serial suite: **378 passed, 0 failed, 0 ignored across 21 targets**, including one doctest; sum of reported target durations **527.81 s** (longest integration target **204.88 s**), **no command timeout**, **no environmental skip messages**. Logs `/tmp/cte-tp8/{check,fmt,clippy,release,tests}-final3.log`; `git diff --check` passed. Initial strict Clippy (`clippy-final.log`) found one **audit-harness-only** reversed literal range warning; the reversed-range check now receives runtime `black_box` bounds, retains its actual `InvalidRange` assertion, and final Clippy and the entire five-command verification were rerun successfully. Earlier audit-harness compile errors and the over-broad manifest probe are detailed above; no full-suite failures were suppressed. A clean suite does not overturn the confirmed imported-realloc oracle failure; no permanent regression currently asserts the missing invariant.

## 8–10. Limits, integration checklist, final verdict

- [x] Schema v2 and supported V2.1, journal record-only, AST-on/off, static DWARF/AST and evidence-fusion candidates, same-trace borrowed refs, raw positions and 128-entry page rejection independently checked.
- [x] Crash, stop-limit partiality, unknown fork descendants, unreadable/truncated memory *contracts* and independent Valgrind scope remain explicit; validated semantic queries do not treat a same-line AST match as executed, a pointer address as allocation origin, or an observed-PID list as a fork census. Not every environment/every byte pattern was independently generated in this bounded audit; existing live/synthetic regression coverage supplements it.
- [x] New real 3143-event instruction workload, repeated loads, four readers, RSS and release-profile query allocations measured; no parser whole-trace RAM guarantee is inferred from the engine export cap.
- [ ] **Before integrated Stage 1 approval:** targeted repair and failing-before/passing-after import regression for TP8-F01; preserve incomplete histories as unavailable; rerun focused fresh-oracle probe, required Cargo commands and release benchmarks. Reassess B → A only after evidence matches raw event relations.
- [ ] Final Stage 1 integrated audit, Semantic Engine, GUI and architecture are **out of scope/not started**.

**Final verdict: B — Conditional.** TP-1–TP-7 provide a generally useful bounded, uncertainty-aware foundation, but a clean deep-validation report plus `Definite` realloc predecessor can currently certify an imported relationship that contradicts the source event. This release-blocking false-semantic-certainty case must be addressed before calling the entire parser ready to feed an unrestricted final Stage 1 integrated audit. The engine release closure remains approved under its separately stated scope; this audit does not alter it.
